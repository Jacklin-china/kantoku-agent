## 0. 这份任务书怎么读

两条线**目标不同、验收不同、责任人不同**，混在一起做就会出现"体验改了一半、后端契约没跟上"或者"后端做完了、界面还是老样子"。

| 线 | 一句话目标 | 验收语言 | 主要落点 |
|---|---|---|---|
| **P 线 产品设计** | 一个创作者能不能顺畅走完一次创作，并愿意再来一次 | 任务完成率 / 用时 / 出错次数 / 主动复用 | `frontend/src`、文案、信息架构 |
| **B 线 后端与论文** | 系统能不能被论证：可回溯、可恢复、可交付 | 断言、指标、可复现脚本 | `src/kantoku`、`tests`、`docs` |

三条交界规则（避免双线互相等）：

1. **契约由 B 线定，判据由 P 线定。** 比如"作品能否恢复"由 B 线定义接口与错误码，"恢复入口放在哪、恢复后落在哪个页面"由 P 线定义。
2. **P 线不得在前端推导状态**（IV-1）。需要新状态就先提 B 线，不允许用 `phase`/`draft`/`onBase` 组合绕过去。
3. **每期只允许一条线先动 3 天**，另一条线按已定契约并行，不允许串行等待。

## 0.1 方向判断（v1.1，我对你三条提议的独立判断）

你说"我的判断可能会错，你自己判断"——逐条给结论，其中一条我改了上一版的口径。

| 你的提议 | 结论 | 理由 | 落地口径 |
|---|---|---|---|
| 会员才能用自填 Key | **模式成立，但表述必须改** | 这本质是**软件授权**，不是卖模型。TypingMind、Chatbox 这类工具就是 BYOK + 授权，用户接受。反例是把它说成"解锁你的 Key"，那才是过路费 | 对外只说「软件授权 / 买断」；**付费钩子按能力卡**（作品数、批量、导出、历史深度、并发），次数只作为免费档的防滥用配额，**不拿次数当卖点**——按次数卖会让用户觉得每点一下都被收费 |
| 用户管理系统（登录/购买/套餐） | **成立，但别做成 CRUD 后台** | 单机单账号阶段后台只有你自己看，投入产出低；真正卡住的是「账户状态 + 权益 + 订单」三件套 | 先做账户域四表与权益服务，后台放最后，只做四项只读 |
| 三档套餐 | **改为两档 + 买断** | 你没有人做套餐运营，三档的定价与权益维护成本翻倍，用户决策也更慢 | 免费 / 专业（订阅）+ 永久买断，作为"不想订阅"的出口 |

**产品方向（本期唯一目标）：做成本地优先的「授权制」创作工具——免费档能完整走通一次创作，付费买规模与效率。不做 SaaS。**

三条理由：

1. 代码现状全是单机假设（SQLite + WAL 单写、本地文件台账、单账号、`TaskRunner` 双线程）。转 SaaS 不是加个登录页，而是换存储、换任务模型、换并发语义——那是另一个项目。
2. 毕设要论证的是"系统设计与实现"，运营不是评分项；把精力投在可论证的架构上回报更高。
3. **免费档能走通全流程，才是"完整性"的产品定义**——这也是答辩现场最好演的东西：从一句话到一支带镜头、带版本、可导出的漫剧。

免费 / 付费边界（只定结构，价格待你定）：

| 能力 | 免费（永久） | 专业 |
|---|---|---|
| 作品数 | 1 个 | 不限 |
| 单日画面 | 3 张 | 不限（受供应商配额约束） |
| 密钥 | 1 个 | 多 Key + 备用切换 |
| 版本历史 | 最近 5 版 | 完整版本树与对比 |
| 导出 | 单张 / 单文件 | 批量与整包 |
| 故事编排 / 视频 | 只读查看 | 可编辑提交 |
| 队列 | 普通 | 优先 |

判据一句话：**免费用户能不能做出第一幕**。能，说明这个免费档是诚实的；不能，免费档就只是试用。

## 1. P 线 · 产品设计

### 1.1 先承认一个张力

README 写的价值主张是「减少创作者在多个工具之间反复复制设定」。但当前主路径是：
生成 Image Prompt → **复制到 ChatGPT / 即梦** → 生成 → **回传上传**。跨应用往返正是它想消灭的动作。

这不是 bug，是**定位尚未收敛**。`ComicShotGeneration.vue` 已经支持两种模式：

- `imageMode='provider'`：站内调供应商出图，失败后有「继续查询原任务 / 重新生成」，完成后显示「图片成本 ¥x」；
- `imageMode='external'`：生成 Prompt → 「复制生图 Prompt / 复制 Codex 工作任务」→ 「上传图片」。

两种模式并存但没有引导，用户不知道自己该走哪条。产品线的第一件事是**把这个选择做成显式决策**，而不是让界面替用户猜。

### 1.2 三个决策点（需要拍板，不定就无法开工）

| 编号 | 决策 | 选项 | 判据 | 建议 |
|---|---|---|---|---|
| **D1** | 主路径走哪条 | A 站内生图为主，外部为备选；B 外部交接为主，站内为可选；C 双轨并列但加选择引导 | ① 目标用户有没有供应商 key；② 单张成本谁承担；③ 出图质量可控性 | **C 起步**：首次进入用一个选择卡说明差异（要不要花钱、图在谁手里），默认记住上次选择。理由：现在两种都实现了，强行二选一会浪费已有能力，且学生环境多为外网工具 |
| **D2** | 首页是会话还是作品 | A 会话优先（现状）；B 作品优先；C 双栏：左作品右对话 | ① 用户回访目的（继续旧活 vs 开新活）；② 三个月后能否找回作品 | **C**：作品列表常驻左侧，对话仍是主舞台。理由：`listComicWorks()` 已存在，只差入口；改造成本低于重排工作台 |
| **D3** | 失败后自动重试还是人工确认 | A 自动重试 N 次；B 人工确认后重试；C 只对"确定未扣费"的失败自动重试 | ① 重复扣费风险；② 用户等待耐受 | **C**：`unknown` 账单绝不自动重试（现有实现已正确），明确失败给一键重试。理由：与预算台账的 `unknown` 语义一致 |

### 1.3 体验断点（按用户旅程，证据来自代码与界面）

| # | 断点 | 现状证据 | 设计动作 | 判据 |
|---|---|---|---|---|
| X1 | 首次进入不知道从哪开始 | 首页即对话输入框；无示例作品、无模板 | 空态给三个"一键开始"：做个角色 / 做个场景 / 导入已有图 | 新用户 60s 内发出第一条有效指令 |
| X2 | 双模式无解释 | `imageMode` 由上游决定，界面无对比说明 | 选择卡：花不花钱 / 图在谁手里 / 能不能改 | 首次选择后不再反复询问 |
| X3 | 跨应用交接无状态 | 只有「复制 Prompt」「上传图片」两个孤立按钮 | 交接状态机：待复制 → 已复制 → 待回传 → 已导入；复制后自动切到"等待回传"并置顶上传区 | 交接环节不出现"我到底做到哪了" |
| X4 | 失败只有两个按钮 | 失败后仅「继续查询 / 重新生成」，原因是一行 error | 失败卡三段：发生了什么 / 为什么 / 下一步（`remedy` 驱动） | 80% 失败可在界面内自行解决 |
| X5 | 费用事后才知 | 完成后显示「图片成本 ¥x」，生成前无预估 | 生成按钮旁显示"预计 ¥x · 余额 ¥y" | 无"意外扣费"投诉路径 |
| X6 | 找不到旧作品 | 作品列表只在工作台内部 | 首页左栏作品列表 + 搜索 | 30s 内找到任意历史作品 |
| X7 | 术语过重 | DirectorSpec / Critic / 门禁 / 产物 | 主路径换词，术语进详情与 tooltip | 主路径零术语 |
| X8 | 长任务必须盯着 | 无标题角标、无完成提醒 | 标题角标 + 任务中心红点 + 完成后内联提示 | 切走 10 分钟回来能看到结果 |

| B-09 | 缩略图与强缓存 | `/thumb` + `immutable` | 30 张图列表首屏 < 2s |
| B-10 | CI 全量 + OpenAPI 快照 + 覆盖率 | 工作流 | CI 绿，覆盖率可读 |
| B-11 | 账户域迁移与四张表（plans / subscriptions / orders / credentials） | 版本化迁移块 + 升级前备份校验 | 旧库升级不丢数据；`credentials` 表内无明文 |
| B-12 | 权益服务：纯函数 `entitlements()` + 6 个门禁点 | `require_entitlement` + `reason` 输出 | 未付费返回 `plan_required` 而非 500 |
| B-13 | 密钥元数据 + 校验探针 + 失效降级路由 | 校验接口 + 主备切换 | 主 Key 失效自动切备用，且界面可见 |
| B-14 | 订单状态机与幂等 | `request_id` 唯一索引 + 回调幂等 | 重复提交只产生一单；失败重试订单号不变 |
| B-15 | 订阅周期与额度刷新任务 | 幂等刷新 + 对账 | 补发不重复；`unknown` 不抵扣额度 |
| B-16 | 账户域安全：字段级脱敏 + 导出排除 + 账户删除可恢复 | 脱敏中间件 + 30 天可恢复 | 日志与导出包无 Key 片段 |

> **一个必须提前想清楚的运营后果**：密钥密文在 **Windows 凭据管理器**里，是**按机器**存的。用户换电脑或重装系统后，数据库还在、Key 全丢（视频 AccessKey 甚至只在内存里）。
> 对策（B-13 附带）：提供可选的「加密密钥包」导出——用用户口令派生密钥加密，导入时重新落进 OS 凭据库。不做这个，用户迁移一次就会骂人；但也不能做"云端同步"，那会把单机产品拖进账户安全责任。

## 5. 不做

- 不做多用户、多主题、多语言
- 不做桌面推送（用标题角标替代，避免新依赖）
- 不为设置页加无后端支撑的开关
- 不在 P 线做"重设计"，只做断点修复；视觉改版属下一阶段
- 不用"截图好看"替代判据，不为通过验收放宽门禁或把 `unknown` 当 0

## 7. C 线（账户与商业化，v1.1 修订）

详细页面规格见 [账户·密钥·套餐与购买设计](account-plan-key-design.md)。这条线性质与 P/B 不同：**它是产品范围扩张，不是体验优化**，因此单列，不并入 8 周。

| 期 | 内容 | 判据 | 预估 | 依赖 |
|---|---|---|---|---|
| C-1 | 密钥管理（三类 provider 放开，元数据 + 校验 + 停用） | 校验失败不丢输入；DB 无明文 | 5d | B-11、B-13 |
| C-2 | 权益门禁 + 只读降级（含 `reason` 文案） | 未付费点生成给 `plan_required` tooltip 而非报错 | 6d | B-12 |

| C-4 | 两档 + 买断的套餐页与用量归属 | 免费用户能走完第一幕 | 4d | C-2、B-15 |

合计 24 天。三条前置条件：

1. **Q2 必须先答**：是否接受新增 4 张账户/交易表（与 `AGENTS.md`「不新增业务表」冲突）。我的判断是应当接受——这属于账户域而非漫剧业务域，混入 `artifacts`/`trace` 会让对账与迁移不可控。但你不同意我就不动，改用 JSON 存配置的方案会显著降低可维护性，需在论文里如实说明。
2. **排序**：C 线整体排在 M3（01-18）之后。若要在 8 周内塞入 C-1/C-2，只能牺牲 P-10（版本对比）、P-11（键盘）、P-12（无障碍）与 B-09（缩略图）。我的建议是**不要牺牲 P-10**，因为它是"付费买到的价值"最直观的演示项。
3. **唯一硬依赖**：C-2 必须复用 `available_actions`，不允许前端另写套餐判断。因此 C-2 最早只能在 B-01/B-02 之后开工。

#### 商业逻辑必须写进套餐页的一句

付费理由只能是**软件本身**（版本可追溯、资产复用、故事与镜头编排、导出与批量）。套餐页若写成"开通才能使用你的 Key"，等于把自己定位成过路费——这是转化率最大的风险点，也是这条线唯一需要产品判断而非开发判断的地方。
